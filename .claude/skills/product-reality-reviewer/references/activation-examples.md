# Selection examples

Use these when checking description boundaries. They are editorial selection
fixtures, not measured evidence that a runtime selected the skill.

| Request | Expected selection and reason |
| --- | --- |
| What is missing from this app for a customer using it the first time? | Select: audience, starting knowledge and task gaps |
| Walk a returning customer through resuming an interrupted project. | Select: continuity and recovery in a built experience |
| Does this native app make repeated work efficient for experienced users? | Select: relevant power-user tasks and platform interaction |
| Our landing page reads like an architecture document. Help it sell the actual value. | Select: buyer reasoning, proof and next action |
| Review this PRD for setup, account and support assumptions. | Select: original plan-review mode |
| Fix the clipped sentences in this paragraph without changing the argument. | Use make-copy-and-media-human; select this skill only if an audience/product gap emerges |
| Debug this database transaction. | Use a code/debugging skill |
| Make the button corners rounder. | Use visual design/implementation guidance |
| Tell me the conversion lift from a screenshot. | Do not claim a measured lift; offer a hypothesis-based page review if wanted |
| Estimate market size without a product artifact. | Use market research rather than this artifact-review skill |
